# Changelog

Release notes for the Chatty platform and API.

## November 2026

### 2026-11-10 — Enterprise-Grade Reliability, Circuit Breakers & Request Idempotency

- **Distributed Circuit Breaker Engine**:
  - Independent circuit breakers protect against cascading downstream outages across **Gemini**, **OpenAI**, **Anthropic**, **OpenRouter**, **WooCommerce**, and **Slack**.
  - Fast-fails requests when an external API is degraded, preventing connection exhaustion and thread starvation.
  - Automatic exponential backoff and half-open probing to smoothly restore healthy traffic.

- **Request Idempotency Engine (`Idempotency-Key`)**:
  - Full support for `Idempotency-Key` and `X-Idempotency-Key` headers on state-mutating requests (payments, lead capture, chat messages).
  - Returns `409 Conflict` on concurrent duplicate in-flight requests and replays cached completed responses with `Idempotent-Replayed: true`.

- **Structured JSON Logging & Automated Secret Scrubbing**:
  - Enterprise log formatter emits single-line JSON logs with ISO timestamps, latency (`duration_ms`), client IP, and `request_id`.
  - In-memory regex scrubbing ensures Bearer tokens, API keys (`chatty_sk_`, `ck_`, `cs_`, `xoxb-`), and credit card numbers never leak into stdout or log aggregators (Datadog, CloudWatch, ELK).

- **Deep Health & Readiness Probes**:
  - Standardized Kubernetes/Cloud Run endpoints: `/health/live` (liveness), `/health/ready` (database and circuit breaker readiness), and `/health/deep` (comprehensive APM telemetry).

### 2026-11-09 — Slack Real-Time Escalation Suite & Full Read-Only WooCommerce REST API Engine

- **Bi-Directional Slack Escalation**:
  - Connect Slack Incoming Webhooks or Slack Bot Tokens (`xoxb-`) per bot under **Dashboard → Integrations → Slack**.
  - **Block Kit Escalation Cards**: Formatted alerts dispatch immediately upon keyword triggers, sentiment drop, or explicit visitor takeover request, featuring visitor metadata, sentiment badge, and recent transcript context.
  - **Interactive 1-Click Actions**: Support agents can claim conversations (**Take Over**) or close them (**Resolve**) directly from Slack without opening the dashboard.
  - **Real-Time Slack-to-Visitor Relay**: Agent thread replies in Slack are instantly pushed into the visitor chat widget via WebSockets and logged in the shared inbox.
  - **Flow Builder Action Nodes**: Automate escalation via `action.slack` nodes inside custom routing flows.
  - **HMAC Signature Security**: Cryptographic request verification with replay attack prevention (`X-Slack-Signature` and timestamp checks).
  - See the complete [Slack Escalation Guide](/guides/slack) for setup instructions.

- **10-Category Read-Only WooCommerce REST API Engine (`wc/v3`)**:
  - **Products & Live Filters**: List products, lookup by ID or SKU, filter by category/tag, search queries, `featured=true`, `on_sale=true`, `stock_status=instock`, and ordering by popularity, rating, or date.
  - **Product Variations**: Real-time inspection of sizes, colors, dynamic sale prices, and stock counts per variation.
  - **Taxonomies & Attributes**: Browse categories, tags, attributes, and terms (Brand, Size, Material).
  - **Reviews & Ratings**: Fetch customer reviews, star ratings, and verified buyer status.
  - **Shipping & Gateways**: Store configuration lookups for shipping zones, methods, classes, and payment gateways with sanitized customer-facing outputs.
  - **Protected Orders & Customer Profiles**: Look up order status, tracking, and customer records with strict server-side email/phone ownership verification.
  - **Coupons & Promotional Integrity**: Validates individual promo codes by code lookups without exposing unauthenticated bulk coupon dumps.
  - See the comprehensive [WooCommerce Guide](/guides/woocommerce) for all endpoints and query parameters.

## October 2026

### 2026-10-30 — Multi-Gateway In-Chat Payments & Product Catalog Sync

- **Native Gateway Integrations**: Connect **Stripe**, **Lemon Squeezy**, and **Polar.sh** directly under Dashboard → Integrations with one-click credential validation and test-mode toggles.
- **Automated Catalog & Pricing Plan Synchronization**: Chatty automatically queries connected gateways to import all active products, billing tiers, and recurring subscriptions into the platform.
- **In-Chat Payment Cards**: Interactive, responsive checkout cards (`[CHECKOUT_LINK:{...}]`) with clear line-item names, formatted amounts, trust seals, and direct 1-click checkout buttons.
- **Live Inbox Payment Generator**: Dual-mode payment modal in the Agent Inbox allowing human agents to search pre-synced products or generate custom one-time amounts on the fly.
- **AI Agent Payment Restrictions & Policy Control**: Dedicated policy toggle (`ai_payment_allowed`) and transaction ceilings (`ai_max_amount_cents`) to prevent autonomous prompt injection exploits and mandate human takeover for financial actions.
- **Enterprise Fintech Security**: Fernet AES-256 secret encryption at rest, dashboard key masking, HMAC webhook signature verification, and zero raw cardholder footprint (PCI-DSS Level 1 compliant).
- **PayPal added** (Orders v2, sandbox and live) for custom-amount checkouts.
- **Lemon Squeezy**: custom amounts now attach to an existing product variant (required by its API); the catalog lists each variant with its real price.
- The Inbox checkout picker only offers gateways you have connected.
- Security hardening: validated gateway identifiers in outbound URLs, sanitized payment logs, and a linear-time email check in the widget.
- See the complete [Payment Gateways & Checkouts Guide](/guides/payment-gateways) for setup details.

## August 2026

### 2026-08-31 — Per-member dashboard permissions

- Team roles (`admin`/`agent`) now actually control access: each invited member's dashboard tabs
  (Inbox, Knowledge, Customizer, Settings, Voice Agent, Team, Billing, BYOK, Webhooks) are
  individually grantable, editable any time by the owner or an admin with the Team permission.
- **Admin** defaults to everything except Billing, BYOK keys, and Webhooks — those stay owner-only
  unless explicitly granted.
- **Agent** defaults to Inbox only.
- Deleting a conversation now requires owner/admin — an agent can reply but not erase history.

---

### 2026-08-30 — Native voice calls in the mobile SDKs (v1.1.0)

- `ChattyVoiceCallView` (iOS, React Native) and `ChattyVoiceCallScreen` (Android) — a live,
  full-duplex voice call with the bot, matching the web widget's voice call experience: real-time
  transcript, mic level meter, mute/hang-up controls, themed per the bot's active design.
- Opt-in per platform via a separate dependency (`ChattySDKVoice` product on iOS,
  `io.livekit:livekit-android` on Android, `livekit-client`/`@livekit/react-native` peer deps on
  React Native) — apps that don't use voice don't pay for LiveKit's footprint.
- See [Mobile SDKs → Voice calls](/guides/mobile-sdks#voice-calls) for setup per platform.

---

### 2026-08-17 — Live voice calls on the web widget

- Enable **Voice Agent** for a bot and a phone icon appears in the widget header — tapping it
  starts a live, full-duplex spoken conversation with the bot right inside the widget (real-time
  transcript, mic level meter, mute/hang-up), no extra embed code required.
- Same feature now ships identically on WordPress (via the shared `widget.js`) and all three mobile
  SDKs — see the entry above.
- Distinct from voice **messages** (a visitor recording and sending one audio clip in text chat) —
  both can be enabled together.

## July 2026

### 2026-07-07 — API v1 security & new endpoints

**Security hardening**
- Per-key scopes: `chat`, `read`, `write`, `admin`. Keys default to `chat,read`. Admin scope satisfies any scope check.
- IP allowlist per API key (CIDR or exact IP supported via the `allowed_ips` field).
- Sliding-window rate limits: 120 req/min per IP, 60 req/min per key.
- Audit log: every public API call is written to `chatty_api_audit_log` with key, bot, endpoint, method, IP, request ID, status code, and latency.
- Security headers on all responses: CSP `default-src 'none'`, HSTS with preload, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`.
- `X-Request-ID` header echoed or generated on every response.

**New endpoints**
- `GET /api/v1/conversations/{session_id}` — fetch a single thread
- `DELETE /api/v1/conversations/{session_id}` — clear a session
- `GET /api/v1/knowledge` — list knowledge sources
- `POST /api/v1/knowledge` — add text or URL source
- `DELETE /api/v1/knowledge/{source_id}` — remove a source
- `GET /api/v1/analytics` — aggregated message/session/lead totals
- `PATCH /api/v1/api-keys/{key_id}` — update key name, scopes, or IP allowlist

**API key management**
- `POST /api/v1/api-keys` now accepts `scopes` and `allowed_ips` fields.
- `GET /api/v1/api-keys` now returns `scopes` and `allowed_ips` per key.

## June 2026

### 2026-06-28 — BYOK (Bring Your Own Key)

- Support for customer-owned API keys for OpenAI, Anthropic, Google Gemini, and OpenRouter.
- Keys encrypted at rest with AES-256-GCM.
- Write-only: stored key is never returned to the client.
- Remove key at any time to revert to Chatty's shared inference pool.

---

### 2026-06-15 — Webhooks

- Bot-level webhook endpoints: register URLs to receive `lead.created`, `message.user`, `message.assistant`, `session.started`, `session.ended` events.
- HMAC-SHA256 payload signing with your webhook secret.
- Automatic retry with exponential back-off (7 attempts over ~8 hours).
